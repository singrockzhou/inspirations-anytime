# 灵感随时记 · 微信小程序（本地存储版）

按《灵感随时记 · 需求分析与产品设计方案 v1.0》落地的可运行工程：原生小程序，无云开发依赖，所有数据落在 `wx.setStorageSync` + 本机用户目录，导入即可跑通「记录 → 浏览 → 查看 → 编辑 → 删除 / 撤销」全链路。

---

## 一、怎么跑起来

1. 微信开发者工具 →「导入项目」→ 目录选本文件夹（`灵感随时记-完整版/`）。
2. AppID 填自己的；没有公众号主体就点「测试号」或「不使用云服务 / 无 AppID」。
   - 工程里预置的是 `touristappid`，仅供无 AppID 预览，正式上传前必须换成自己的。
3. 编译后首屏就是卡片流，点顶部「今天想到什么？」或底部并排的「写一句 / 说一段 / 拍一张」即可记第一条。

> 不需要开通云开发，不需要配置服务器域名，不需要登录。

## 三、数据模型与存储

记录的字段刻意压到最小，够用且不给自己挖坑：

```js
{
  id: 'r1a2b3c4d5e6f',   // 本地主键，时间前缀便于排查
  type: 'text',          // text | voice | photo，一条只允许一种
  content: '',           // 文字正文 / 照片配文 / 语音备注，最多 1000（语音照片 200）
  mediaPath: '',         // 语音/照片的本机持久路径，文字为空
  duration: 0,           // 语音秒数
  size: 0,               // 媒体字节数
  createdAt: 1760000000000,
  updatedAt: 1760000000000,
  deletedAt: 0           // 非 0 即软删，列表与统计都不再计入
}
```

| 存储键 | 内容 | 说明 |
|---|---|---|
| `lg.records.v1` | 记录数组（平铺、不分片） | 1000 条上限，一次同步读写；软删记录留在数组里等清理 |
| `lg.meta.v1` | `{ firstAt }` | 「开始记录」日期 |
| `lg.draft.v1` | 文字草稿 | 300ms 防抖，关掉小程序也不丢 |

媒体文件不塞进 Storage（10MB 上限且 base64 会膨胀），统一落在 `wx.env.USER_DATA_PATH` 下，库里只存路径。

## 四、四条核心链路与关键代码

### 1. 创建（`pages/record/record.js` → `onSave`）

- 三种形态共用一页：`type` 切换时若已有内容会二次确认「刚才的X会清掉」，杜绝一条记录混两种形态。
- 文字：`textarea` 自动聚焦、`maxlength=1000`、无标题无分类。
- 语音：默认按住说话（松手即存、上滑 60px 取消），可切换为点击录音；实时计时，60s / 240s 各震一下但**不打断**；到 300s 由 `RecorderManager` 自动收尾。
- 照片：`chooseMedia` → `compressImage` → `saveFile` 落盘，配文可选。
- 保存走「先落库、再返回」，不弹"保存成功"，只在列表里让新卡片闪一次底色（`flashId` → `highlight`）。

```js
const rec = mode === 'edit' ? store.update(id, payload) : store.create(payload)
if (!rec) return                       // 失败已在数据层提示，页面不重复弹窗
this.saved = true
store.clearDraft()
getApp().globalData.flashId = rec.id   // 交给首页做一次性高亮
this.leave()
```

### 2. 浏览（`pages/index/index.js`）

- 吸顶伪输入条：1 次点击进文字态，滚动时不消失（`position: sticky`）。
- 按自然日分组（今天 / 昨天 / 11月3日），首屏 20 条，触底再 +20（`onReachBottom`）。
- 文字超 6 行折叠为「展开」，短句不出现该按钮。
- 下拉刷新用系统回弹，不额外加重试逻辑。

### 3. 查看与编辑

- 卡片点击进 `pages/detail/detail`，展示完整正文、播放录音、大图预览。
- 编辑入口有两处：详情页「改一改」、列表长按「改一改」。都复用 `record?mode=edit&id=`。
- 编辑只改 `content`（语音/照片可换媒体），**`createdAt` 永不变**，所以列表顺序不会因为改一句话而跳动；真的改过才在卡片上标「改过」。

### 4. 删除与撤销

```js
// 数据层：软删，不立刻销毁
function remove(id) { /* deletedAt = Date.now() */ }

// 首页：5 秒倒计时条 + 撤回
deleteItem(item) { store.remove(item.id); this.refresh(); this.showUndo(item.id) }
onUndo() { store.restore(this.pendingDeleteId); this.refresh() }
```

`app.js` 在启动和切后台时跑 `store.purge()`，物理清除超过 24 小时的软删记录，并顺手删掉它们的媒体文件——避免"删了但空间不还"。

## 五、与 PRD v1.0 的对应关系

| PRD 条目 | 落地情况 |
|---|---|
| 三种记录形态（文字/语音/照片）、单条单类型 | ✅ |
| 卡片流按日分组、相对时间、6 行折叠 | ✅ |
| 伪输入条 1 次点击进输入态 | ✅ |
| 长按 → 复制 / 删除 + 5 秒撤销 | ✅ |
| 空态一句话 + 直接入口 | ✅ |
| 语音不截断、计时、60s/240s 提示、300s 上限 | ✅ |
| 弱网/无网先存本机 | ✅（本地存储版本天然离线，不存在待同步态） |
| 上限 1000 条、媒体压缩 ≤300KB | ✅（压缩目标 quality 70；1000 条上限硬拦） |
| 第 7 天回访、订阅消息、回顾页 | ⛔ 本工程不做，见第六节 |
| 标签 / 搜索 / 打卡 / 分享 / AI | ⛔ 按 PRD 明确不做 |

### 两处有意偏离，需要你知道

1. **PRD 写"不做编辑"，这个版本做了。** 需求方明确要求"创建、编辑、查看、删除"，所以补上编辑。为不破坏「8 秒记一条」的产品假设，做了三点约束：编辑入口全部下沉到长按与详情页（首屏主路径仍是"写一句就存"）；编辑不改 `createdAt`，列表不跳动；卡片上加「改过」标记，让"修饰过的文字"和"原始捕捉"在视觉上可区分。
2. **记录面板从"半屏升起的 sheet"改成独立页面。** 小程序里页面级 sheet 要自己扛键盘顶起、滚动穿透、返回手势三件事，坑比收益多；当前实现是独立页 + 自绘顶部栏（取消 / 存下），键盘弹起行为与 sheet 一致，返回即回列表，观感差别很小。要真做成 overlay，可把 `record` 的 WXML 搬进 `components/record-sheet` 在首页 `wx:if` 弹出，数据层不用动。

## 六、已知限制（写在这里，避免上线后当 bug 排查）

1. **数据只在本机。** 卸载/重装小程序、清理微信存储、换手机都会丢。这是"零后端"的代价，PRD 的 1000 条容量与多端同步都需要服务端。
2. **本机媒体有配额。** `wx.saveFile` 落在用户目录，总量有限（旧版 10MB 量级），照片压缩后约 200–300KB，几十张就会触顶。触顶时 `saveFile` 失败会降级为临时路径，本次会话可见、重启后失效。要长期存图必须上对象存储（PRD 第六节）。
3. **照片/相机需在后台配置「用户隐私保护指引」。** 未配置时真机上 `chooseMedia` 会直接失败（开发者工具里一般不拦）。录音同理需要声明麦克风用途。
4. **回访链路没接。** 第 7 天订阅消息、站内回访卡、回顾页需要云函数 + 定时触发器，工作区里另一份 `灵感随时记-小程序/` 就是那套云开发实现，可作为后续合并的基础。
5. **没有全文搜索。** PRD 把它放在 v1.1（人均 >50 条再做）。当前数据量下靠日期分组翻找更快。

## 八、列表分组、删除与数据搬移（v1.1）

### 8.1 分组规则

按「由近及远」切四个时间桶，命中即止，不做二次细拆：

| 桶 | 判定 | 展示 |
|---|---|---|
| 今天 | 自然日差 ≤ 0（含手机时间超前产生的未来记录） | 卡片平铺，最上面 |
| 本周 | 与本机同一自然周（**周一为起点**），且不是今天 | 堆叠组，折叠 |
| 本月 | 同一自然月，且不在本周 | 堆叠组，折叠 |
| 今年 | 同一年，且不在本月 | 堆叠组，折叠 |
| 往年 | 更早的年份，各年一组，如「2025年」 | 堆叠组，折叠 |

边界说明：上周日不算「本周」而落到「本月」；12 月 31 日与次年 1 月 1 日一定是两个不同的年桶。

实现位置：`utils/date.js` 的 `bucketOf` / `groupBuckets`，纯函数，`now` 可注入，便于验证。

### 8.2 堆叠样式

折叠态用三层卡片边缘错落叠放（`scale` 0.90 / 0.95 / 1.00，透明度 0.45 / 0.72 / 1），最上层露出该组最新一条的角标、时间与一行摘要，右下角标「还有 N 条」。点击组头或整块堆叠即展开为完整卡片列表。

### 8.3 删除的三条路径

| 入口 | 交互 | 保护 |
|---|---|---|
| 单条 | 卡片**向左滑**，露出红色「删了」按钮，点它删除；滑不够距离自动回弹 | 5 秒撤销条 |
| 单条 | 长按卡片 → 菜单里的「删了」 | 5 秒撤销条 |
| 整组 | 组头右侧「删整组」→ 二次确认弹窗（写明分组名与条数） | 5 秒撤销条，撤回可**整组恢复** |

- 同一时刻只允许一条卡片处于左滑打开状态，由页面的 `openSwipeId` 统一调度。
- 删除是软删（打 `deletedAt`），24 小时后才由 `app.js` 的 `purge()` 连媒体文件一起物理清除。
- 批量删除只写一次盘，中途失败不会留下"删了一半"的状态。

### 8.4 换设备：导出 / 导入

入口在「我的 → 换手机」。

**导出**：把所有记录打成一个 JSON。图片和录音无法跨设备引用本地路径，因此读成 base64 内嵌。
- 单条媒体上限 2MB、总计上限 15MB，超出的只迁文字，并在结果弹窗里如实报数量。
- 手机端用 `wx.shareFileMessage` 转发到「文件传输助手」；桌面端用 `wx.saveFileToDisk` 直接存盘。

**导入**：从聊天记录里选那个 `.json`（`wx.chooseMessageFile`），校验文件头 → 还原媒体到新机沙箱 → 按 id 合并。
- **只做新增，不覆盖**：同 id 已存在则跳过，所以反复导入同一份不会产生重复，也不会冲掉新手机上刚记的内容。
- 导入后会自动把「开始记录」时间修正到更早的那条。

实现位置：`utils/transfer.js`（打包/解包）+ `utils/store.js`（`importRecords` / `removeMany` / `restoreMany`）。

## 九、检索、回顾与输入增强（v1.2）

### 9.1 数据结构的变化

记录从「单一媒体」升级为「一组媒体 + 三个新字段」：

| 字段 | 含义 |
|---|---|
| `mediaPaths: string[]` | 照片最多 9 张；语音仍只用 `mediaPath` |
| `tags: string[]` | 从正文里的 `#标签` 自动解析，最多 8 个 |
| `starred: 0\|1` | 星标，钉在「星标」筛选里 |
| `archivedAt: number` | 非 0 表示已归档，不进主列表但不算删除 |

老数据不需要迁移：`store.js` 的 `normalizeRecord()` 在读取时补齐这四个字段，`mediaPath` 会自动升级成 `mediaPaths: [mediaPath]`。

### 9.2 标签怎么写

正文里直接写 `#读书`、`#产品想法`，保存时自动归好，列表卡片上会显示前 3 个。
标签字符集：中英文数字，遇空格或 `，。！？、` 等标点即止，单个标签最长 12 字。

### 9.3 五个新入口

| 位置 | 作用 |
|---|---|
| 首页顶部放大镜 | 进搜索页：全文搜索 + 标签快捷筛选 + 命中高亮 |
| 首页筛选条 | 全部 / 星标 / 归档 / 单标签，四个维度互斥切换 |
| 首页「那年今日」卡 | 自动出现去年或前年同一天的那条，点开看全文 |
| 我的 → 随便翻一条 | 随机重温，偏向 7 天以上的旧记录，可加星、转发 |
| 我的 → 从聊天存一条 | 从微信聊天里选文件/图片，直接存成灵感 |

### 9.4 长图分享

卡片长按 → 「做成图」，或详情页 → 「做成图」。
`utils/poster.js` 用 Canvas 2D 排版：750 宽、高度按内容算、正文最多 26 行、带标签与页脚。
生成后可保存到相册，或走 `wx.showShareImageMenu` 直接发给朋友。

两个技术点值得记一笔：

- canvas 2d 每次改 `width/height` 都会重置上下文，所以必须「先量高 → 再定尺寸 → 再绘制」，量的时候用临时高度。
- `drawImage` 只吃 `canvas.createImage()` 出来的 Image 对象，喂路径字符串画不出来，因此 `poster.loadImage(canvas, src)` 必须先取尺寸再等 `onload`。

### 9.5 转发与接收

所有页面的转发都会带一段正文进去：`/pages/index/index?inbox=<encodeURIComponent(正文前 400 字)>`。
接收方打开小程序会看到「收到一条分享」，确认后存成自己的一条本地记录——因为数据本来就只在本机，跨设备只能靠"把内容带过去"，不能靠同步。

### 9.6 语音转文字：说清楚边界

小程序没有「给一个音频文件、还一段文字」的能力。真正可用的只有微信同声传译插件（`WechatSI`），而它是**边录边转**、不能事后转写。

所以这里的实现分两层：

- **默认可用的**：语音记录下方就是文字备注框；详情页对没有文字的语音/照片提供「补一句文字」。补上之后这条就能被搜索命中，这是"语音可检索"的实际达成路径。
- **需要额外两步的**：`utils/asr.js` 里把 `USE_PLUGIN` 改成 `true`，并在 `app.json` 增加 `plugins` 声明、在小程序后台添加该插件。启用后录音会边录边出字，最终文字直接写进正文。未启用时按钮不会出现，不会出现"点了没反应"。

### 9.7 每日提醒：只做了能做的那一半

订阅消息必须由**服务端**下发。客户端能做的只有「请求授权 + 记住时间」，真正到点弹出通知要靠自建服务端或云函数按 openid 发送。

因此：

- `utils/remind.js` 顶部留了 `TMPL_ID`，填上小程序后台创建的模板 ID 才会真正请求授权；
- 没填时，点「每日提醒」会如实说明还差一步，并把时间偏好记下来；
- 我的页的「提醒时间」可以正常选，选完会持久化，等模板配好就生效。
