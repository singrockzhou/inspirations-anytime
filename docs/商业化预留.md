# 商业化预留设计：免费版不动，新增功能收费

> 约束：**当前发布版本的全部功能永久免费**。付费只卖给"以后新加的能力"，不回收任何已经给出去的东西。
> 这份文档说明代码该怎么分层、权益怎么判定、边界画在哪里，以及怎么防止以后被自己人破坏。

---

## 一、三条不可退让的约束

| 约束 | 具体含义 | 破坏它的典型做法 |
| --- | --- | --- |
| **免费功能不回收** | 今天能用的记录、搜索、标签、左滑删除、导出 JSON、长图分享，以后任何一个版本都必须能用，不需要登录、不需要联网 | 把"导出"改成会员功能；把搜索限流到 50 条 |
| **数据永远可携带** | 本地数据是开放 JSON，免费版也能导出、也能导入；付费功能写进去的字段，免费版要能"看不懂但不弄坏" | 用私有二进制格式；免费版一读就崩 |
| **计费点只挂在外部队列** | 收费只针对"要花服务器钱/第三方钱"的能力（云同步、AI、转写、OCR、协作） | 给本地写一条记录加次数限制 |

第 3 条是产品判断：本地功能收费会让用户立刻算清"这破功能值不值"，并且伤害口碑；云和 AI 是持续成本，收费正当且用户能理解。

## 二、分层：依赖只能向下

```
pages/*            UI，只负责展示与触发
   ↓
features/*         业务编排（同步、AI 摘要、批量导入…）
   ↓
edition.js         权益策略：能不能用、用多少、不能用时怎么降级
   ↓
services/*         云函数调用、上传下载、第三方 API
   ↓
store.js / media.js  本地数据与文件（绝不知道"付费"这回事）
   ↓
wx.*               平台能力
```

两条硬规定：

1. `store.js`、`media.js` **不许** `require('edition')`。数据层不认识商业模式，才能保证"哪天不卖了，数据还在"。
2. 页面**不许**写 `if (edition.paid)`。页面只调用 `edition.guard(featureId)`，否则将来改定价要改 30 个文件。

## 三、三个概念：Feature / Edition / Entitlement

| 概念 | 是什么 | 存在哪 |
| --- | --- | --- |
| Feature | 一个可售卖的能力，如 `sync.cloud`、`ai.summarize` | 代码里的常量表（编译进包） |
| Edition | 版本档：`free` / `pro` / `team` | 常量表 + 远端配置 |
| Entitlement | 某个用户此刻的实际权益，带到期时间 | 服务端签发，客户端只缓存 |

**本地必须有一份编译进包的默认值**：没网、首次启动、请求失败时，`free` 就是兜底。远端配置只能"收窄"（把 beta 关掉），不能凭空"扩容"——扩容必须走带签名的 entitlement，否则改包就能白嫖。

### 3.1 Feature 注册表

```js
// utils/edition.js
const FREE = 'free'

/** 每加一个能力，只在这里登记一行；页面不写死档位 */
const FEATURES = {
  // 已经有的一律 FREE，冻结
  'record.local':    { min: FREE, note: '本地记录（永久免费）' },
  'search.local':    { min: FREE, note: '本地搜索（永久免费）' },
  'export.json':     { min: FREE, note: '换机导出（永久免费）' },

  // 以后新增的
  'sync.cloud':      { min: 'pro', meter: 'records', fallback: 'local-only' },
  'ai.summarize':    { min: 'pro', meter: 'calls',   fallback: 'disabled' },
  'asr.long':        { min: 'pro', meter: 'minutes', fallback: 'disabled' },
  'export.pdf':      { min: 'pro', meter: null,      fallback: 'disabled' }
}

const EDITIONS = {
  free: { rank: 0 },
  pro:  { rank: 1 },
  team: { rank: 2 }
}
```

`fallback` 字段是**降级行为**，比"报错"重要：会员过期时云同步不是崩掉，而是变成"本地可用、云只读"。

### 3.2 唯一判定入口

```js
function can(featureId) {
  const f = FEATURES[featureId]
  if (!f) return false                 // 没登记 = 不存在，宁可错杀
  const mine = entitlement()           // { edition, expiresAt, quotas }
  if (Date.now() > (mine.expiresAt || 0) + GRACE_MS) return f.min === FREE
  return rank(mine.edition) >= rank(f.min)
}

/** 页面里唯一该出现的东西：拿不到就走付费引导，拿到就继续 */
async function guard(featureId) {
  if (can(featureId)) return true
  const r = await dialog.confirm({
    title: '这是「专业版」的能力',
    text: FEATURES[featureId].pitch || '升级后可用，免费版已有的功能不受影响。',
    cancelText: '先不用',
    confirmText: '看看专业版'
  })
  if (r.confirmed) wx.navigateTo({ url: '/pages/pro/pro' })
  return false
}
```

页面里的写法：

```js
onSync() {
  if (!(await edition.guard('sync.cloud'))) return
  ...  // 正常业务
}
```

### 3.3 权益从哪来、怎么防伪

- 服务端是唯一真相：支付回调 → 写 `entitlements` 表 → 返回**签名凭证**（HMAC/JWT），字段至少包含 `openid / edition / quotas / issuedAt / expiresAt / nonce`。
- 客户端只做两件事：缓存凭证、检查 `expiresAt`。**不做**"本地解锁"，不做"改个布尔值就变会员"。
- 真正扣量必须在云函数侧：客户端传来的 `featureId` 只作为"用户想干什么"，额度、频率、去重由服务端判定。
- 换设备 = 换 openid 拉一次凭证；恢复购买按钮就是"重新拉一次"。
- 离线宽限建议 3–7 天：断网时凭缓存的 `expiresAt` 放行，超期只降级，不锁数据。

### 3.4 微信生态的合规红线

- 小程序内**虚拟支付**受平台规则约束：iOS 端不得引导站外支付、不得售卖虚拟内容（以当期规则为准，上线前必须复核）。
- 稳妥做法：安卓走微信支付；iOS 只展示"该功能在 iOS 暂不可购买"，或把付费点设计成"实物/服务"类。
- 订阅消息、客服消息不能当营销通道用；续费提醒要走合规模板。

## 四、计费点怎么选

| 候选 | 成本性质 | 建议 | 理由 |
| --- | --- | --- | --- |
| 云同步 / 多端 | 服务器 + 存储，随用户线性增长 | **首选** | 用户能感知"东西在云端"，且成本真实 |
| AI 摘要 / 自动标签 | 按 token 计费 | 推荐 | 单次成本可见，额度好解释 |
| 长语音转写 / 批量 OCR | 第三方按分钟/张计费 | 推荐 | 天然按量 |
| 导出 PDF / 精美长图模板 | 一次性开发 | 可选 | 适合做"轻付费"尝鲜包 |
| 多人共享 / 协作空间 | 服务器 | 适合 team 档 | 有组织付费场景 |
| 主题 / 字体 / 图标包 | 一次性开发 | 谨慎 | 容易被截图传播，且伤"免费"观感 |
| **本地记录条数、搜索、导出 JSON** | 零边际成本 | **禁止** | 违反第一条约束 |

定价结构建议：`free`（现在这些）→ `pro` 年付（云 + AI 额度）→ `team`（协作 + 管理）。**不做永久买断**，否则后面的服务器成本没人付。

## 五、版本、灰度与远程配置

```
客户端包（不可变）                 远端（可变）
FEATURES 默认档位     ←──收窄──    flags.json
免费功能清单（冻结）                灰度桶 / 定价实验
```

- 远端配置只放**开关**和**桶号**，不放价格文案（价格改动要能即时生效但必须走审核/配置中心版本）。
- 每个付费能力都要有 kill switch：出故障时一行配置关掉，页面回到免费路径而不是白屏。
- 灰度按 `openid` 哈希分桶，同一用户始终落在同一桶，避免"一会儿能用一会儿不能用"。
- 版本号语义：`major` 改数据 schema，`minor` 加功能，`patch` 修 bug。免费功能的可用性只允许随 `minor` 增加，不允许减少。

## 六、数据兼容：付费功能不能污染免费数据

1. 所有新字段**可选**，读取端缺字段要有默认值（现有 `normalizeRecord()` 已经是这个模式）。
2. 旧客户端写回时要**保留未知字段**，不能因为不认识就丢掉（否则用户在两台设备间来回会丢数据）。
3. 付费能力的产物单独放新 key，例如 `lg.sync.v1`、`lg.ai.v1`，不要塞进 `lg.r.v1.*` 的记录分片。
4. 会员过期后的降级路径要写死：
   - 云同步：本地继续可写，云端只读 30 天，之后按策略清理并在到期前 7 天提醒导出。
   - AI 结果：已经生成的摘要/标签属于用户数据，**过期不删**，只是不能再生成新的。
5. 导出永远包含全部字段，包括付费功能产生的字段——这是"数据可携带"的底线。

## 七、工程护栏（防止半年后自己破坏规则）

| 护栏 | 做法 |
| --- | --- |
| 单一判定入口 | `grep -r "edition.paid" pages/` 必须为空；只允许 `edition.guard(` / `edition.can(` |
| feature id 常量 | 禁止字符串散落，统一 `FEATURES`，lint 校验 `guard('...')` 里的 id 必须已登记 |
| 免费功能回归 | 现有 27 条对话框行为测试 + 免费路径冒烟（记录/搜索/导出/导入）纳入每次发版 |
| 权益矩阵测试 | 表驱动：`free/pro/过期pro/伪造token/离线` × 每个 feature，断言 `can()` 结果与降级行为 |
| 埋点 | `paywall_view` / `purchase_start` / `purchase_success` / `restore` / `quota_exceeded` / `downgrade` |
| 对账 | 每次放行写一条 `{openid, feature, edition, tokenId, ts}` 的审计日志，支付流水与放行量能对上 |
| 客户端不可信 | 所有额度在云函数二次校验；客户端 `can()` 只用于"提前告诉用户"，不作为安全边界 |

## 八、反模式清单

1. **把现有功能挪进付费墙** —— 一次就够毁掉口碑，且老用户会截图对比。
2. **页面里到处 `if (pro)`** —— 定价一改要全量回归。
3. **只在客户端校验额度** —— 改包即白嫖，服务器账单会教你做人。
4. **把权益写进本地 storage 明文** —— 等于把钥匙挂在门上。缓存可以，但必须是签名凭证。
5. **会员过期就锁数据** —— 用户的第一反应是"我的东西被绑架了"，第二反应是差评。
6. **一次上三个付费点** —— 归因不了到底哪个值钱；先上一个，跑满 4 周数据再加第二个。

## 九、落地顺序（不改现有体验）

| 阶段 | 动作 | 对现有版本的影响 |
| --- | --- | --- |
| 0（现在） | 只写这份文档 + 在 README 标注边界；不动代码 | 无 |
| 1 | 加 `utils/edition.js`（全部 feature = free），页面零调用 | 无 |
| 2 | 接远端 flags，只放 kill switch，不接支付 | 无 |
| 3 | 第一个付费点：云同步（本地功能完全不依赖它） | 免费用户可继续只用本地 |
| 4 | 第二个付费点：AI 摘要/标签，额度制 | 同上 |
| 5 | 定价实验（月/年/首年优惠），按桶灰度 | 只影响新用户 |

每一步都可以停：即使商业化失败，第 1–2 阶段的代码也只是"多了一层判断"，随时能删。
