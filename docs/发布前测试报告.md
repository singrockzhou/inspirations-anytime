## 三、发现的问题

### 已修（3 项）

1. **正文首尾空白未归一化**（本次修复）
   `store.normalizeRecord` 原来只做 `typeof === 'string'` 判断。从剪贴板、聊天文件导入的文字常带首尾空行，落库后表现为：卡片顶部多一条空白、导出的 Markdown 多一个空段落、分享标题以空格开头（微信会吃掉空格导致标题变形）。
   修法：在 `normalizeRecord` 统一 `trim()`——`create` / `update` / `importRecords` 三条写入路径都经过它，一处收口。
   回归：`flow.test.js` 第 1 组断言钉住。

2. **导出不含归档**（上一轮已修）
   `exportBackup` 用的 `store.list()` 默认排除归档，用户归档过的内容从不在备份里，换手机后静默消失。
   修法：`store.list({ includeArchived: true })`，记账口径同步改成含归档条数。

3. **缺少录音权限用途说明**（本次补齐）
   `app.json` 没有 `permission.scope.record.desc`，授权弹窗与审核说明里缺"为什么要麦克风"。
   修法：补上描述文案「录下你说的那句话，存成一条语音灵感，只留在这台手机上」。

### 设计取舍（1 项，非缺陷）

4. **`sitemap.json` 全站 `disallow`**
   微信不会索引任何页面，搜索曝光只靠名称、简介、关键词。
   判断：**保持现状**。首页就是用户的私人灵感列表，开放索引等于把私人内容递进搜索结果。这是隐私设计，不是遗漏。
   若将来想增加页面级曝光，只能放开不含用户内容的页面（例如一个介绍页），不要放开首页。

### 观察项（3 项，暂不处理）

5. **同一毫秒创建的两条记录排序不确定**
   `sortDesc` 只按 `createdAt` 比较，相等时靠 V8 稳定排序保持存储顺序（旧的在前面）。人手不可能同毫秒记两条，批量导入可能遇到。影响是"同毫秒的两条顺序可能反了"，不影响数据完整性。建议不改（加 id 次级键会让跨设备顺序更随机）。

6. **搜索页输入定时器未在 `onUnload` 清理**
   `search.js` 的 `this.timer` 只在下次输入时清。页面在 200ms 内被退出，回调会对已卸载页面 `setData`——微信只告警不崩。低危，可后续统一处理。

7. **复制后出现两次提示**
   `wx.setClipboardData` 自带系统 toast「内容已复制」，我们又弹了自定义 toast「复制了 N 条」。轻微视觉重复，若要精简可去掉自定义那条。

## 五、审核风险提示

1. **审核员打开是空态**
   本地工具类小程序的典型被拒原因："页面空白 / 功能不完整"。首次打开没有数据，首页只有一句引导。
   对策：提审「版本描述」里写清楚，并附操作路径（见下）。
2. **提审备注建议原文**
   > 本小程序为纯本地灵感记录工具，不联网、不登录、无服务端，所有内容由用户本人创建，因此首次打开为空列表属正常。验证路径：首页「今天想到什么？」→ 输入任意文字 → 保存 → 返回列表可见；「我的 → 关于小程序」可查看作者信息。数据仅存于本机，需麦克风（语音记录）、相册（拍照）、剪切板（从剪贴板收一条）三项权限，用途已在《用户隐私保护指引》中声明。
3. **不要出现"经营"痕迹**
   个人主体不能做经营性内容。界面里不要出现价格、会员、购买、打赏入口（当前没有）。
