# 小程序内「模板 / 指南 / FAQ 三页」做搜索收录引流的可行性评估

> 评估对象：灵感随时记（微信小程序，纯本地、无后端、无登录）
> 评估时间：2026-11-26
> 依据：微信官方 sitemap / 内容接入文档、本项目源码、用户提供的 11 张截图
> 标注约定：**已核实**（有出处）/ **推断**（我的判断，无直接出处）/ **待确认**（缺信息）

## 一、先给结论

| 问题 | 结论 |
|---|---|
| 截图方案方向对不对 | **对**。对一个纯本地工具，"静态内容页 + sitemap 白名单"是唯一不需要后端的收录路径 |
| 按截图做完就能被收录吗 | **不能**。本项目 `sitemap.json` 现在是**全站 disallow**，页面收录开关开着也不会收任何页面。这是截图作者看不到的硬阻塞 |
| 值不值得做 | **值得做，但理由要换**。模板库的真实价值是"解决打开首页不知道写什么的空态"，收录是顺带的；只为收录造页面，投入产出比很差 |
| 现在就该做吗 | **不建议排在第一位**。1.8.5 还没发布，线上还带着剪贴板读不到、多图变多条两个毛病。先发版，再做模板库 |
| 预期收益量级 | 首月很可能接近 0，两三个月后每月几十到几百访问是合理区间（推断，无数据支撑），不是"几千流量" |

## 二、截图里的核心改造点（还原成 7 条）

1. **新增三类纯静态内容页**：模板库（10–20 个）、使用指南、FAQ。内容写死在 `js/json` 常量里，不从 storage 读，不依赖后端。
2. **页面必须真实可达**：首页空态下方、首页顶栏或底部、我的页都要有真入口；只在后台推路径而界面上找不到，等于影子页。
3. **每个详情页满足四要素**：标题带关键词（`wx.setNavigationBarTitle`）、正文 ≥ 300 字真实文本、可分享（`onShareAppMessage`）、有转化动作（"用这个模板记一条"跳编辑页并预填）。
4. **数量克制**：10–20 个精品，不要批量生成"换标题不换内容"的页面，重复低质会被判低质。
5. **六个收录条件**：正式版代码包、不依赖本地数据、不需登录授权、路径可直接打开、文字是真实文本节点、首屏即见正文。
6. **两个坑**：别在内容首屏触发隐私授权（弹窗会挡住爬虫）；别用动态参数在 `onLoad` 里现拼内容。
7. **验收**：跑真机 + 后台收录数 + 换没打开过小程序的微信号搜关键词。

此外截图还给了一个五件事的排序（容量仪表盘 → 图片存文件系统 → 模板/指南/FAQ → 虚拟支付 → 观察两周）。**这个排序和"引流"目标不是一回事**，见第七节。

## 三、机制核实：三条路完全不同，别混

搜索结果里混着三种能力，很容易看错。

### 3.1 sitemap 被动抓取（本项目唯一可走的路）

**已核实**（微信官方 sitemap 文档，经 people.cn 镜像与腾讯云技术文章转述一致）：

- 小程序根目录的 `sitemap.json` 配置页面是否允许被微信索引；
- 没有该文件 = 所有页面可被索引；`{"action":"allow","page":"*"}` 是优先级最低的默认规则；
- 支持 `allow` 指定页 + `disallow` `*` 的组合（官方例 3），即"只有我点名的页面能收"；
- 爬虫访问时携带 `user-agent: mpcrawler`、场景值 `1129`；
- **原文关键句**：「若小程序爬虫发现的页面数据和真实用户的呈现不一致，那么该页面将不会进入索引中」；
- 免责声明原文：「如因开发者未遵循声明……导致用户的个人信息被展示披露、未经授权被访问或泄露，一切法律责任应由开发者承担」。

这条不需要申请、不需要资质、不需要后端。

### 3.2 后台「页面收录」总开关

**多来源一致、未取到官方原文**：小程序后台 → 功能 → 页面内容接入 → 基础设置 → 「页面收录」，默认开启，可整体关闭；「接入概况」看收录数据。

**待确认**：你的后台这一项到底是开还是关。截图作者说"你已经开了"，但那是他的判断，不是你的确认。

### 3.3 「内容接入」主动推送（本项目基本不用想）

**已核实**（官方《内容接入》页）：准入要求包括**非个人主体**、限定一级类目（政务/商业服务/医疗/金融/文娱/社交）、**月均日活 ≥ 5000**、上架超 30 天、以图文资讯为主营业务，还要推 300 条测试数据过审。

本项目是小工具、个人或小体量主体，**明确不满足**。所以别在"主动推送"上花时间。

另外「页面路径推送」这个能力，2022 年的文章说已下线，2021 年的社区帖还在引导使用——**当前状态待确认**，不要写进方案。

**结论：只有 3.1 那条路可用，而它当前被自己的 `sitemap.json` 堵死了。**

## 四、对照本项目：六个条件逐条过

| 条件 | 现状 | 判断 |
|---|---|---|
| 正式版代码包 | 线上 1.8.4，1.8.5 开发中 | ✅ 已满足（收录只认线上版，**推断**：开发版/体验版不对外，爬虫不会抓） |
| 不依赖本地数据 | 现有 7 个页面几乎全依赖 storage | ⚠️ 现有页面不行，**新增三页必须自带常量** |
| 不需登录/授权 | 无登录、无账号 | ✅ 天然满足 |
| 路径可直接打开 | `pages/detail/detail?id=xxx` 依赖 storage，直接打开是空的 | ⚠️ 现有页面不行；新增页要能裸开 |
| 文字是真实节点 | 卡片正文用 `<view>`/`<text>` 渲染 | ✅ 满足（`card.wxml` 用 `<view class="body">`） |
| 首屏即见正文 | 现有列表有分组折叠（stack 折叠态只露一行摘要） | ⚠️ 新增页不要做折叠/"展开全文" |

### 4.1 硬阻塞：`sitemap.json` 全站 disallow

当前文件（`miniprogram/sitemap.json`）：

```json
{
  "desc": "本地工具类小程序，无需被微信索引",
  "rules": [{ "action": "disallow", "page": "*" }]
}
```

这意味着：**即使后台收录开关是开的，微信也不会收录任何一页。** 截图里"收录开关你已经开了"这句话，在代码层面等于没开。

### 4.2 反向风险：不能图省事改成 `allow *`

首页列表卡片会渲染用户的灵感正文（`card.wxml` 的 `{{item.content}}`），详情页渲染全文。一旦 `allow *`，这两类页面就进入爬虫的可见范围。

理论上，爬虫设备上没有用户的 storage，渲染出来是空态，「数据与真实呈现不一致」这条会把它们挡在索引外。但**不能拿这个当隐私保护**：官方免责声明把责任划给开发者，而且"理论上不索引"和"承诺不索引"是两件事。

正确写法只能是白名单（见 8.1）。

## 五、潜在价值：值多少，怎么算

### 5.1 直接价值（搜索流量）

**推断，无数据支撑**，只用于量级判断：

```
月访问 ≈ 收录页数 × 单页月曝光 × 点击率 × 落地页转化率
```

- 收录页数：8–20
- 单页月曝光：工具类长尾词，乐观 50–200
- 点击率：搜索结果里小程序的点击率通常低于网页，按 5%–15%
- 落地页转化（点"用这个模板记一条"）：20%–40%

乐观区间：20 页 × 200 × 15% ≈ 600 访问/月；保守区间：接近 0。**首月大概率是 0**，因为收录本身要时间，且新页面没有权重。

### 5.2 间接价值（这一项更确定）

- **空态流失**：工具类最大的漏点是首次打开后的前 30 秒。模板库直接对着这个洞。
- **差评来源**：FAQ 回答"数据存哪、会不会丢、换手机怎么办"——这三个问题现在一定在被问。
- **分享传播**：模板详情页配 `onShareAppMessage` 后，用户可以把"某模板"转给朋友，比转首页更有理由。

**判断：先把模板库当产品功能做，收录是副产品。** 截图里那句自查标准很准："如果这页永远不会被收录，我还会做它吗？"

## 六、风险与限制

| 风险 | 说明 | 应对 |
|---|---|---|
| **隐私泄露** | 首页/详情页含用户正文；`allow *` 会放进来 | 只白名单三页，其余显式 disallow；上线前用开发者工具看每页的"是否被索引"提示 |
| **收录为 0** | sitemap 只管"允许"，不保证"收录"；官方没承诺周期 | 别把 KPI 定成收录数；先看产品指标 |
| **低质判定** | 20 篇模板若互相换词、或抄网上写作教程，会被判低质，反而更差 | 自己写 300 字，宁可朴素；先 8 篇跑通 |
| **审核风险** | 内容页写"分享给三个朋友解锁"之类会违规 | 不做任何诱导分享话术 |
| **爬虫发现不了带参页** | 官方只说明会爬、带 UA 和场景值，没说会穷举参数（**推断**） | 列表页用真实 `<navigator>` 指向每个详情，别只靠 JS `navigateTo` |
| **"收录开关"没开** | 后台状态未知 | 上线前去后台确认一次 |
| **维护成本** | 内容页需要更新，否则越来越旧 | 模板本身不过时，指南/FAQ 随版本改 |
| **`site:` 查收录不可靠** | 截图让你用 `site:你的appid` 查——**微信搜索不是网页搜索，没有 `site:` 操作符**（未找到任何官方支持说明） | 用后台「接入概况」+ 换微信号真搜 |

## 七、优先级判断（和截图排序有分歧）

截图给的顺序是：容量仪表盘 → 图片存文件系统 → 模板/指南/FAQ → 虚拟支付 → 观察两周。

**它对"产品完整度"是对的，对"引流"是错的**，而且漏了本项目最要紧的一件事：

1. **1.8.5 必须先进线上**（剪贴板读不到、多图变多条，这两个是线上正在发生的体验事故）。收录页做得再好，用户进来第一件事是"粘贴失败"，等于漏斗底部漏水。
2. **容量仪表盘 / 图片存文件系统**：这两个解决的是"数据会满"的长期问题，不解决获客。如果目标是引流，它们排在模板库之后。
3. **模板库 + 指南 + FAQ**：唯一同时服务"留存"和"获客"的一项，**应该第一**。
4. **虚拟支付（68 元买断）**：在没有任何流量验证之前开收款，是把转化率当已知数。应该等模板页跑出访问量再开。
5. **观察两周**：必须保留，但要在模板页上线之后。

**我的排序**：发 1.8.5 → 模板库（8 篇）+ sitemap 白名单 + 入口 → 观察 14 天 → 补到 20 篇 + FAQ → 容量/图片（按数据压力决定）→ 支付。

## 八、具体改造方向（文件级，可直接照做）

### 8.1 `miniprogram/sitemap.json` 改白名单

```json
{
  "desc": "只有公开内容页允许被索引；记录列表、详情、搜索等含用户数据的页面一律不索引",
  "rules": [
    { "action": "allow", "page": "pages/tpl/list" },
    { "action": "allow", "page": "pages/tpl/detail" },
    { "action": "allow", "page": "pages/guide/guide" },
    { "action": "disallow", "page": "*" }
  ]
}
```

要点：
- `disallow "*"` 必须在最后（官方例 3 的写法）；
- 首页 `pages/index/index` **不加** allow，它的卡片会显示用户正文；
- `pages/detail/detail` 同样禁止。

### 8.2 新增页面与数据

| 文件 | 作用 | 关键约束 |
|---|---|---|
| `miniprogram/utils/templates.js` | 20 个模板常量：`id / title / sub / scene / example / skeleton` | 纯数据，不 require store |
| `miniprogram/pages/tpl/list.*` | 模板库列表 | 用 `<navigator url="/pages/tpl/detail?k=three-act">`，让爬虫能跟 |
| `miniprogram/pages/tpl/detail.*` | 模板详情 | `onLoad` 只做 `templates[k]` 查表；正文 `<text>`；不调任何隐私接口；不做折叠 |
| `miniprogram/pages/guide/guide.*` | 使用指南 + FAQ（先用一个页面两段，够用再拆） | 同上 |

### 8.3 首页与我的页入口（截图第 3 条）

- 首页空态（`index.wxml` 的 `.empty` 块）在"记下第一条"下面加一行文字链："没有灵感？看看模板 →"；
- 我的页（`me.wxml`）现有 `row tap` 结构，加两行：`使用指南`、`常见问题`，与"导出/导入"同款样式；
- 顶栏已有 3 个文字入口（从聊天存 / 多选 / 我的），**不建议再加第四个**，会让右上角更挤。

### 8.4 模板 → 记录页预填（转化那一步）

`record.js` 目前只认 `mode/id/type/focus/auto`，不支持预填。需要加一个：

```js
// record.js onLoad
const tpl = options.tpl ? templates.byId(options.tpl) : null
if (tpl) this.setData({ content: tpl.skeleton })
```

配套：`wx.navigateTo({ url: '/pages/record/record?mode=create&type=text&tpl=three-act' })`。

注意：预填的是**骨架**（如"1. 起因：\n2. 转折：\n3. 结果："），不是范文——否则用户会存下一堆别人的字。

### 8.5 分享

每个内容页自己写 `onShareAppMessage`，`path` 指回**自己**（带 `k=` 参数），不要指首页。指首页等于把搜索来的流量又丢回漏斗顶。

| 指标 | 采集方式 |

## 十一、验收清单（照抄执行）

1. `sitemap.json` 是白名单：`allow` 三页 + `disallow *`，且 `disallow` 在最后。
2. 首页、详情、搜索、重温、做成图、我的——六页在开发者工具里显示"不被索引"。
3. 每个内容页正文是 `<text>`/`<view>`，字数 ≥ 300，无"点击展开更多"。
4. `pages/tpl/detail?k=three-act` 冷启动直接打开就有内容（不读 storage）。
5. 内容页 `onShareAppMessage` 的 `path` 指回自己。
6. 首页空态、我的页都有真入口，且不是只在后台推路径。
7. 内容页不调用 `wx.requirePrivacyAuthorize`、`wx.getClipboardData`、`wx.chooseMedia`。
8. 后台「页面收录」开关确认开启。
9. 发布正式版后第 7、14 天各看一次「接入概况」。

## 十二、待确认（需要你给，或者去后台看一眼）

1. **后台「页面收录」开关状态**——你看得到，我看不到。
2. **「页面路径推送」现在还在不在**——2021 年有、2022 年有人说下线，当前状态无法从公开资料确认。如果还在，它能显著加快收录；不在就纯等爬虫。
3. **线上真实用户量级**——决定第 5 节的测算取哪一档。没有这个数，所有预期都只能给区间。
4. **是否愿意为 20 篇模板投入写作时间**——这是内容活，不是代码活；8 篇能跑通，20 篇要写一整天。

## 附：一句话总结

截图方案的机制判断基本正确，但它没看到本项目的 `sitemap.json` 是全站禁止索引——**在改这个文件之前，做多少页面都不会被收录**；而改它的时候，最需要小心的不是"收不到"，是"别把用户的灵感收进去"。

### 13.2 与计划的偏离（都是有意的）

1. **没做「复制骨架到剪贴板」。** `wx.setClipboardData` 是隐私接口，为了一个和"用这个模板记一条"重复的功能，多一个隐私调用点不划算。
2. **模板内容只写中文。** 模板是内容不是界面文案，不塞进 i18n 字典；英文界面下页面如实说一句"模板内容是中文的"。
3. **顶栏没加第四个入口。** 计划里写的是"我的页加两行"，实际也是这么做的；首页只动空态，没动顶栏。

### 13.3 仍然待确认（不影响发布，影响效果）

- 后台「页面内容接入 → 基础设置 → 页面收录」的**开关状态**。截图只显示「设置」按钮，看不到开/关。
- 收录是否真的发生、多久发生。官方无承诺周期。
- `pages/tpl/detail` 带 `params` 的写法在搜索侧是否按文档执行。规则本身有官方例 5 作依据，但**没有实测样本**，属于"照文档写、等结果验"。
- **折叠区里的链接能否被抓到。** 折叠用 `hidden`（`display:none`）而非 `wx:if`，节点与链接都留在渲染结果里；但官方没有说明 `display:none` 的内容是否计入。**这是推断。** 若收录长期为 0，先去掉折叠，再怀疑 sitemap。
